# Чат Telegram через GREEN-API

Тестовое задание: простой интерфейс для отправки и получения текстовых сообщений в Telegram.

## Стек

- React + TypeScript (строгая проверка типов)
- Vite
- CSS Modules
- Oxlint

Роутер пока не используется: приложение предполагает форму подключения и экран чата.

## Запуск

```sh
npm install
npm run dev
```

Адрес локального сервера появится в терминале.

## Проверки и сборка

```sh
npm run lint
npm test
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт сборку в `dist`. `preview` запускает локальный просмотр сборки.

## Структура

```text
src/
  App.tsx          # Корневой компонент
  index.css        # Глобальные стили
  main.tsx         # Точка входа
  modules/
    auth/          # Форма подключения, её состояние и проверка инстанса
    chat/          # Создание диалогов, текстовая переписка и очередь уведомлений
  shared/
    api/green-api/ # Общие запросы, ошибки, адрес API и разбор JSON
    storage/      # Чтение и запись локального хранилища браузера
    ui/            # Общие кнопка и поле ввода
  styles/
    colors.css     # Общая палитра Telegram
```

## Цвета

Палитра находится в `src/styles/colors.css` и подключена глобально через `src/index.css`.
Используйте CSS-переменные в стилях компонентов: `color: var(--color-text-primary)`.
Для исходящих сообщений предусмотрены `--color-message-outgoing` и `--color-text-outgoing`.
Светлая тема оформлена в стиле Telegram: синий акцент, белые поверхности,
серые подписи и светло-зелёные исходящие сообщения. Это палитра проекта,
а не точная копия всех тем и версий Telegram.

## Текущее состояние

Реализована форма подключения с полями `idInstance` и `apiTokenInstance`.
Адрес API задан константой `GREEN_API_URL` в `src/shared/api/green-api/config.ts`.
Перед подключением проверьте, что адрес совпадает с `apiUrl` вашего инстанса в личном кабинете.

Общие параметры запросов и таймаут находятся в `src/shared/api/green-api/config.ts`.
Запросы выполняются через `requestGreenApi` из `src/shared/api/green-api/request.ts`:
он формирует URL, применяет настройки и обрабатывает ошибки HTTP, отмену и таймаут.
Разбор ответа в конкретный тип остаётся в API-модуле соответствующей функции.

Данные проверяются методом [GetStateInstance](https://green-api.com/telegram/docs/api/account/GetStateInstance/).
Подключение подтверждается только при состоянии `authorized`. Для остальных состояний,
ошибок HTTP, сети и таймаута показываются сообщения с возможностью повторить попытку.
После успешного подключения учётные данные сохраняются в `localStorage` браузера.
При перезагрузке сохранённые данные повторно проверяются через `GetStateInstance`,
после чего открывается чат. При сетевой ошибке данные остаются в форме для повторного входа.
Кнопка «Выйти» удаляет сохранённую авторизацию.

После подключения открывается чат в стиле Telegram. Получатель задаётся международным
номером телефона. `CheckAccount` определяет его `chatId`, `SendMessage` отправляет текст.
Входящие сообщения получаются через `ReceiveNotification` и подтверждаются методом
`DeleteNotification`. Повторные уведомления не создают дубликаты. Медиа не отображаются.
Enter отправляет текст, Shift+Enter добавляет строку; предел — 4096 символов.
Есть список диалогов, счётчик непрочитанных, статусы исходящих сообщений и выход.
Чаты, сообщения, статусы, счётчики непрочитанных и выбранный диалог сохраняются
в `localStorage` отдельно для каждого `idInstance` и восстанавливаются после перезагрузки.
История остаётся после выхода и становится доступна при следующем входе в тот же инстанс.
Повреждённые данные и несовместимые версии не используются. Если запись недоступна
или закончилось место, приложение продолжает работу и показывает сообщение об ошибке сохранения.
Токен сохраняется в браузере в открытом виде; для удаления токена нажмите «Выйти»,
для удаления всей истории очистите данные сайта. Синхронизация между устройствами не предусмотрена.

В [настройках инстанса](https://green-api.com/telegram/docs/api/account/GetSettings/)
для HTTP API включите `incomingWebhook: yes` и оставьте `webhookUrl` пустым.
Для статусов отправки включите `outgoingWebhook: yes`, для подтверждения факта отправки
через API — `outgoingAPIMessageWebhook: yes`. Приложение проверяет настройки получения
и показывает подсказку, но самостоятельно не меняет их. Ответ `SendMessage` означает
постановку в очередь: до уведомления о доставке сообщение отображается «В очереди».
Статусы также сверяются с `GetMessage`: исходящие сообщения в очереди, отправленные
и доставленные проверяются повторно до прочтения. Между запросами выдерживается секунда,
между проходами — 5 секунд. Это позволяет обновлять доставку и прочтение даже без
уведомления о статусе; прочитанные сообщения и ошибки отправки больше не опрашиваются.
При выходе запросы и ожидания отменяются. Настройки инстанса не меняются.

`npm test` проверяет авторизацию, API чата, разбор уведомлений, дедупликацию,
порядок статусов и отмену ожидания на подменённых ответах, без реальных запросов.
Реальный обмен с Telegram требует подключённого инстанса и пока не проверен.
Для запуска тестов нужен Node.js с поддержкой `--experimental-strip-types` (например, 22.13+).

Не добавляйте токен в исходный код или репозиторий.
